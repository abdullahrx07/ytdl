# y2mate.gs — HAR Traffic Analysis

Source file: `proxypin_export_2026-08-12.har` (17 entries, captured via ProxyPin on iOS Safari)

Full walkthrough of the network flow behind the y2mate.gs YouTube→MP3 converter, as seen in the captured HAR file. This is an **observational breakdown only** — no signing/auth logic reverse-engineered, no client reconstructed.

---

## 1. Page load

**`GET https://y2mate.gs/`**
Plain HTML shell (~2.3KB gzipped). Inline CSS, one form (`video` input + MP3/MP4 toggle + Convert button). All actual logic lives in a deferred external script:

```
/js/1785442237/y2mate.js
```

The numeric path segment is a cache-busting build version tied to the logo asset too (`/svg/1785442237/logo.svg`).

Appears **twice** in the capture — likely the page reloading after a completed download, or the user starting a second conversion.

---

## 2. Auth handshake

**`GET https://eta.etacloud.org/api/v1/auth?_=<timestamp>`**
No credentials sent — just a cache-busting timestamp.

Response:
```json
{"geo":"0","key":"ThppT5Wf4Z9TRgQp","err":0}
```
- `key` — short-lived session token
- `geo` — likely region/geo-block flag
- `err` — 0 = success

CORS locked to `Access-Control-Allow-Origin: https://y2mate.gs` only.

---

## 3. Init (preflight + real call)

**`OPTIONS /api/v1/init`** — CORS preflight, since the follow-up GET carries an `Authorization` header (non-simple request). Server replies `204`, allowing `GET, OPTIONS` and the `Authorization` header for that one origin.

**`GET /api/v1/init`** — sends the token from step 2:
```
Authorization: Bearer ThppT5Wf4Z9TRgQp
```

Response:
```json
{"convertURL":"https://coccoc.etacloud.org/api/v1/convert?sig=...&v=TPiCWUQ78CY&f=mp3", "error":"0"}
```

**Key finding:** the `sig=` value is generated **server-side** and handed to the client fully formed. It is not computed in browser JS — nothing to extract from client-side code even with full reverse-engineering of `y2mate.js`.

---

## 4. Convert — mirror redirect

**`GET https://coccoc.etacloud.org/api/v1/convert?sig=...`**

Response:
```json
{"error":0,"progressURL":"","downloadURL":"","redirect":1,
 "redirectURL":"https://cococc.etacloud.org/api/v1/convert?sig=..."}
```

Note the swapped-letter hostnames: `coccoc` → `cococc`. This is a load-balancer/mirror-pool bounce, not a real job start — `progressURL`/`downloadURL` are still empty.

---

## 5. Convert — job actually starts

**`GET https://cococc.etacloud.org/api/v1/convert?sig=...`** (same sig, correct node this time)

Response:
```json
{
  "error":0,
  "redirect":0,
  "progressURL":"https://cococc.etacloud.org/api/v1/progress?sig=wO97LM...",
  "downloadURL":"https://cococc.etacloud.org/api/v1/download?sig=wO97LM...",
  "title":"পুনর্জন্ম | PunorJonmo - Condropith(চন্দ্রপীঠ) | Official music video."
}
```

**Key finding:** a *second, distinct* signature (`wO97LM...`) is minted here, separate from the `init`-stage sig (`TCt6qMiaDB8...`). Two-tier signing:
- Tier 1 sig → authorizes *starting* a conversion job
- Tier 2 sig → scoped only to *checking/downloading* that specific finished output

This duplicate `convert` call (same sig, same timestamp) appears **twice** in the capture — either a client-side retry/poll or a double-logged connection in ProxyPin.

Target video resolved: **`v=TPiCWUQ78CY`** → "পুনর্জন্ম | PunorJonmo" by Condropith (চন্দ্রপীঠ), Bangla music video.

## Full request sequence (as captured)

```
1.  GET  y2mate.gs/                                    → HTML shell
2.  GET  eta.etacloud.org/api/v1/auth                   → session key
3.  OPTIONS eta.etacloud.org/api/v1/init                → CORS preflight
4.  GET  eta.etacloud.org/api/v1/init                    → pre-signed convertURL
5.  GET  coccoc.etacloud.org/api/v1/convert              → redirect to mirror
6.  GET  cococc.etacloud.org/api/v1/convert              → job-scoped sig + title
7.  GET  cococc.etacloud.org/api/v1/convert (duplicate)   → same result
8.  CONNECT kocmg.com ×5                                 → all failed (tracking)
9.  GET  9hito.com/hid.js                                → fingerprinting script
10. GET  y2mate.gs/ (second load)                        → repeat page load
```

## Architecture summary

- **Frontend:** `y2mate.gs` — static page + JS, no backend logic of its own
- **Backend:** `etacloud.org` subdomains — `eta` (auth/init), `coccoc`/`cococc` (mirror pool for convert/progress/download)
- **Auth model:** Bearer token → server-generated pre-signed URLs (two-tier: job-start sig, then job-output sig) — signing secret never touches the client
- **CORS:** strictly scoped to `https://y2mate.gs` as origin
- **Third-party tracking:** `kocmg.com` (dead/blocked in this capture), `9hito.com` (fingerprinting script)
